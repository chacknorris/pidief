# Launch Checklist

## GitHub publication

- Set repository description to: `Privacy-first PDF merge and annotation in the browser. No uploads, no backend.`
- Add topics: `pdf`, `pdf-editor`, `pdf-merge`, `annotation`, `privacy`, `client-side`, `nextjs`, `typescript`
- Enable Issues and Discussions
- Pin discussions for:
  - roadmap and priorities
  - show and tell
  - feature ideas
- Add screenshots to `docs/images/`
- Confirm license, security policy, contribution docs, and issue templates are visible

## Show HN

- Title suggestion: `Show HN: PIDIEF, a private PDF merge and annotation tool that runs entirely in your browser`
- Prepare a short comment explaining:
  - why local-first matters
  - how PDF.js and pdf-lib make the app possible
  - what workflows it handles today
  - what feedback is most wanted

## Reddit

- Target communities that allow project sharing and PDF/productivity tooling
- Lead with the privacy angle and local processing
- Share a short GIF and a direct workflow example
- Ask for pain points around browser-based PDF editing

## Product Hunt

- Tagline: `Merge and annotate PDFs locally in your browser`
- Prepare 3 to 5 screenshots and a short demo clip
- Emphasize no-upload and browser-only processing in the first line
- Include the roadmap so visitors see active direction

## X / Twitter

- Short launch post:
  - `Built PIDIEF: a lightweight PDF merge and annotation tool that runs entirely in the browser. No uploads, no backend, just local PDF work.`
- Follow-up thread:
  - why privacy-first PDF tooling matters
  - architecture snapshot
  - current limitations
  - call for contributors
